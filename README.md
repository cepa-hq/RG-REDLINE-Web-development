# Roun Groun REDLINE

Brand and website coordination hub for **rg-redline.com**.

REDLINE is the serious, futuristic extreme-performance direction of Roun Groun: safety-oriented equipment, advanced electronics and technical gear for committed adventure users. Read the [brand brief](docs/brand/BRAND_BRIEF.md) before writing copy or designing.

## Confirmed owner brief

- Domain: **rg-redline.com** (owner supplied; DNS/hosting are not verified by this record).
- Platform: **WordPress + WooCommerce**.
- Presentation: **no off-the-shelf presentation theme**; owner describes the site as “without a theme”. Confirm the actual rendering/bootstrap arrangement before implementation.
- Delivery: **pages built one by one**, with coordinated shared components.
- Style: dark, ultra-futuristic, technical and dead serious. No playful parent-brand treatment.

This repository starts as the storage and task ledger for brand and website work. It is not proof that every live WordPress file or database setting is already version-controlled here.

## Every agent starts here

1. Read [AGENTS.md](AGENTS.md), the [coordination workflow](docs/coordination/README.md), the [brand brief](docs/brand/BRAND_BRIEF.md), and [architecture constraints](docs/website/ARCHITECTURE.md).
2. Inspect open Issues, Pull Requests, branches and recent commits; read instructions in the actual implementation repository too.
3. Publish a scoped task plan before editing code, design assets, WordPress pages or settings.
4. Claim exact files, page IDs/routes and shared configuration keys. Resolve overlap before writing.
5. Work on your own branch and preserve other agents’ changes.
6. Record checkpoints, actual validation, deployment state and a scoped rollback.

Issues are the canonical live task ledger. Documentation, exported code and release artifacts support that ledger.

No credentials, private customer data, database dumps, production backups or unrestricted logs belong here. This repository is public. Redact evidence before uploading it.
